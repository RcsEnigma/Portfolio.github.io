# Portfolio

Drop files in a folder, run one command, push to GitHub. Done.

---

## File structure

```
/
├── index.html              — main gallery page (grid, carousel, modal, zoom overlay)
├── page-engine.js          — renders subpages from pages.json (widgets + their own zoom overlay)
├── generate-manifest.js    — the build script; run this after adding/changing files
├── theme.css               — shared color variables, used by subpage stubs
├── page-widgets.css        — subpage widget layout styles
├── manifest.json           — generated: gallery data (don't hand-edit)
├── pages.json              — generated: subpage data (don't hand-edit)
│
├── works/                  — drop gallery images/videos + their .txt files here
│   └── thumbs/              — generated: compressed thumbnails (see below)
│
└── pages/                  — one subfolder per subpage
    └── <page-name>/
        ├── _page.txt         — page-level settings (label, order, featured, carousel)
        ├── 01_widget.txt     — numbered widget files, one per section
        ├── your-media.jpg
        └── thumbs/           — generated: compressed thumbnails for this page

/<page-name>/                — generated stub at the repo root for each subpage,
    └── index.html             giving it a clean URL like yoursite.com/page-name/
```

Everything under `thumbs/` and the root-level subpage stub folders (`/<page-name>/index.html`) is generated by `generate-manifest.js` — don't edit those by hand, they get overwritten/cleaned up automatically on the next run.

---

## Setup (do this once)

1. Put everything in a folder and push it to a GitHub repo
2. In your repo settings, enable GitHub Pages (Settings > Pages > Deploy from main branch)
3. Install Node.js from nodejs.org if you don't have it
4. Install image compression: open a terminal in your portfolio folder and run `npm install sharp`
5. Add a `.gitignore` file with `node_modules/` in it so that folder doesn't get committed

---

## Adding a new work

1. Drop your image/video file into `/works/`
2. Drop a `.txt` file with the same name into `/works/`
3. Run `node generate-manifest.js` in a terminal pointed at the folder
4. Commit and push with GitHub Desktop

That's the whole loop every time.

## The .txt file

Every field is optional. You can use any combination.

```
[title]
My Work Title

[description]
Whatever you want to write here.
URLs like https://yoursite.com/page automatically become clickable links.

[tags]
3D, animation, sci-fi

[date]
2024-11

[featured]
true

[square]
true

[link]
https://vimeo.com/whatever

[extra]
mywork_02.jpg, mywork_03.mp4
```

**What each field does:**

`[title]` - shows on hover and in the popup. defaults to filename if you leave it out.

`[description]` - shows in the popup info panel.

`[tags]` - comma separated. they show up as filter buttons on the site. selecting multiple tags filters to works that have ALL of them (not any of them).

`[date]` - any string. works sort newest first by this field.

`[featured]` - set to true and it shows up in the big carousel at the top of the page.

`[square]` - set to true to force a 1x1 square grid cell regardless of the image's actual dimensions.

`[link]` - shows as a clickable link in the popup.

`[extra]` - list extra files to bundle into this same gallery entry (comma separated filenames).

---

## Grouping multiple files together

Two ways to do this:

**Numbered filenames** - name your files `project_01.jpg`, `project_02.jpg`, `project_03.mp4` with the same base name. They'll automatically bundle together. The lowest numbered one becomes the thumbnail.

**The [extra] field** - list additional filenames directly in the txt file. Useful when the files have different names.

---

## Grid sizes

The grid automatically picks a span based on the image's real dimensions. Landscape goes wide, portrait goes tall, square stays square.

You can override it with `[square]\ntrue` in the txt file to force a 1x1 cell.

---

## The carousel

The big carousel at the top shows any work with `[featured]\ntrue` in its txt file. It also shows any subpages (see below) that have `[featured]\ntrue` in their `_page.txt`. Clicking a work slide opens its popup. Clicking a subpage slide takes you to that page.

## Thumbnails and image compression (speeds up loading, prevents crashes)

After running `npm install sharp`, the script automatically generates compressed images in a `thumbs/` folder next to your source files (`works/thumbs/` for the main gallery, `pages/<page-name>/thumbs/` for subpages). There are two tiers:

**Display tier** — `<name>.webp`, capped at 1200px on the long side, WebP quality 82. Used by the grid, carousel, and the modal popup, for every file in a multi-file gallery entry (not just the first one).

**Zoom tier** — `<name>_zoom.webp`, capped at 4096px on the long side, WebP quality 90. This is what the pan/zoom overlay opens when you click/tap to zoom in.

Why zoom needs its own tier, and why it's capped rather than just compressed: the zoom overlay renders its image inside a layer that the browser promotes to the GPU for smooth panning. That means the browser has to allocate a texture sized to the image's **decoded pixel dimensions** — not its file size. A photo can be a small file and still have enormous pixel dimensions (or vice versa), and either way, a big enough one can exceed an older phone's texture/memory limit and crash the tab, even though it's only ever shown scaled down on screen. Re-encoding to WebP shrinks bytes on disk and speeds up the download, but it does nothing about that decode-time memory footprint — only capping the actual pixel dimensions does. 4096px is comfortably past what any screen can show pixel-for-pixel even at max pinch-zoom, so this shouldn't look like a quality loss in practice. If you want more true full-resolution headroom on capable devices (at the cost of reintroducing crash risk on old ones), raise `ZOOM_MAX_PX` at the top of `generate-manifest.js`.

The zoom tier is generated for **every** image, including subpage widget images, regardless of that widget's `[compress]` setting — `[compress]` only controls the display-tier thumbnail, since the zoom-tier cap is a stability safeguard rather than a look/quality choice.

If sharp isn't installed, or a zoom-tier image fails to generate for some reason, the zoom overlay falls back to the raw original file — so it still works, just without the size cap.

GIFs are skipped for both tiers (compressing them kills the animation) — they always load as their original file.

For videos, if you have ffmpeg installed on your system, it'll extract a poster frame as a thumbnail. If not, it just skips it.

Thumbnails (either tier) are only regenerated if the source file is newer than the existing thumbnail, so it's fast on subsequent runs.

## Subpages

You can make custom project pages that live at `yoursite.com/pagename/`.

Create a folder inside `/pages/` with the page name. Inside it, put:
- `_page.txt` for page-level settings
- Numbered `.txt` files for each section/widget on the page
- Your media files for that page

Run `node generate-manifest.js` and the page stub gets created automatically. Delete the source folder and run again and the stub gets cleaned up automatically.

### _page.txt

```
[label]
Studies

[order]
1

[featured]
true

[carousel_media]
hero.jpg

[carousel_caption]
A short description for the homepage carousel slide.
```

`[label]` - the name shown in the nav and at the top of the page.
`[order]` - controls left-to-right order in the nav (lower number = further left).
`[featured]` - shows this page in the homepage carousel.
`[carousel_media]` - which file to use as the carousel slide image (must be in the same page folder). if you skip this it uses the first image it finds in your widgets.
`[carousel_caption]` - text shown under the title in the carousel slide.

### Widget files

Name them `01_whatever.txt`, `02_whatever.txt` etc. The number controls the order they appear on the page.

```
[type]
image-left

[title]
Section Title

[text]
Body text goes here.

[media]
myimage.jpg

[background]
#1a1a1a

[compress]
false
```

`[type]` - picks the layout (see below).
`[title]` - section heading.
`[text]` - body copy.
`[media]` - file(s) to use. some types need more than one.
`[background]` - hex color for the section background. if it's a light color the text automatically switches to dark so it stays readable.
`[compress]` - set to false to skip thumbnail generation for this widget's images. defaults to true.

### Layout types

`image-left` - image on left, text on right. on mobile stacks image above text.

`text-left` - text on left, image on right. on mobile stacks image above text.

`split` - text in the middle, one image on each side. needs two files in [media]. on mobile stacks them vertically.

`media-only` - single centered image or video with playback controls.

`full-bleed` - edge to edge media with a big title overlaid in the center.

`text-only` - centered text block, no image.

`carousel` - film strip carousel. center item is large and uncropped, neighbors peek in from the sides. 5 to 7 images works best. on mobile shows 3.

`trio` - three images side by side in equal columns, no text. needs three files in [media]. on mobile stacks them.

`title-bar` - big centered heading, good for dividing sections.

### Images are zoomable on subpages

Clicking any image in a widget opens the same full pan/zoom view as the main gallery. Scroll to zoom, drag to pan, Esc or the X button to close.

## Colours and text

All the colour variables are in the `:root` block at the top of `index.html`. Same variables are in `theme.css` for subpages. If you change them, update both files.

About and Contact page text is in `index.html`, search for `about-page` and `contact-page`.

---

## If the subpage looks out of date after pushing

Run `node generate-manifest.js` before pushing. The script stamps a version number on the stylesheet and script links in each subpage stub, so browsers and CDNs always fetch fresh copies.

---

## Local preview

Browsers block fetch() on file:// URLs so opening index.html directly won't load your data. Use a local server instead:

```
npx serve .
```

## Notes on recent fixes and known behavior differences

**Zoom-overlay crash on older phones (fixed).** The main gallery's zoom overlay (`index.html`) wasn't resetting its on-screen pan/zoom transform when opening a new image — only the tracking variables were reset, not the actual CSS transform applied to the canvas. Combined with the zoom view previously always loading the raw, uncapped original file, this could hand an older device's browser an oversized image to composite at a leftover zoom level, which is a known way to crash Safari on older iPhones. Fixed by (1) resetting and re-applying the transform immediately when zoom opens, and (2) introducing the size-capped zoom tier described above so the overlay never has to composite an unbounded image in the first place.

**Multi-file gallery entries loading full-res images into the modal (fixed).** Only the first file in a multi-file gallery entry (`[extra]` field, or numbered filenames like `project_02.jpg`) ever got a compressed thumbnail. Stepping to the 2nd, 3rd, etc. image loaded the raw original directly into the modal popup. Thumbnails are now generated for every file in an entry.

**Subpage zoom didn't disable native pinch-zoom (fixed).** The main gallery's zoom overlay temporarily disables the browser's native pinch-to-zoom while open (otherwise iOS treats a two-finger gesture as a page-zoom instead of handing it to the custom pan/zoom handler). The subpage widget zoom (`page-engine.js`) didn't have this — it's been added for parity.

**Subpage zoom doesn't blank other on-screen thumbnails.** The main gallery's zoom overlay clears every other visible thumbnail from the page right before loading the zoom image, freeing up memory headroom for the decode. The subpage zoom overlay doesn't do this. This mattered a lot more before the zoom-tier size cap existed; now that the zoom image is bounded, it's a smaller optimization opportunity that hasn't been ported over — worth doing if subpages ever show signs of the same memory pressure.

**Video loading in the modal.** Known separately-tracked issue: video playback in the modal popup (as opposed to zoom) can occasionally fail to load with no visible error, especially on slower connections — `makeVideo()` currently sets no poster image and has no error/retry handling, unlike the grid's video thumbnails. Not addressed in this round.
